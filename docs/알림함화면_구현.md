# 알림함 화면 — 헤더 배지·패널과 전체 목록을 실제 API에 붙인다

> 📝 기준: PRD v0.9 F-35 · API 명세 v0.4 10장 · `web/CLAUDE.md` · 스킬 `mock-to-api` · 2026-10-16
>
> 함께 보는 파일: `알림_구현.md`(먼저 합쳤다, main f420873)

앞 PR에서 알림이 **쌓이기만** 하고 학생 눈에는 아무것도 안 보인다. `GET /notifications`·`POST /notifications/read`는 다 열렸는데 web은 아직 목데이터라, 실제 모드에서 알림함을 열면 늘 비어 있었다. 이번 PR이 그 둘을 잇고, PRD F-35가 말하는 **"모든 알림 확인하기" 전체 목록 화면**을 새로 만든다.

남은 P0 셋(F-33 웹 푸시·F-35 알림함·F-50 LMS) 중 알림함을 먼저 하는 이유는 **네가 준비해 줄 것이 없는 유일한 작업**이라서다. 웹 푸시는 VAPID 키 한 쌍이, LMS는 녹화한 Canvas 응답이 네 손을 거쳐야 시작된다.

**규모와 확인:**
- **web만 바뀐다.** 새 파일 6개, 바꾸는 파일 10개(문서 2개는 "반영하기"에 따로 적었다).
- **DB 변경이 없고 api도 그대로다.** 새 엔드포인트도, 명세·PRD 수정도 없다 — 10장 응답을 그대로 받아 쓴다.
- web `npm run typecheck` 통과, 목 모드·실제 모드 빌드 둘 다 통과(`/notifications` 라우트가 늘어 12개).
- 실제 API를 띄우고 **E2E 29단계**를 돌렸다(본 흐름 12 · 실패·경계 13 · 목 모드 4). 콘솔 오류 없음.
- **되돌림 시험 16가지를 모두 잡았다.** 두 가지는 처음에 놓쳤는데, 하나는 내가 변형을 잘못 만든 것이고 하나는 중복된 코드여서 지웠다(아래).
- 따로 띄운 검토 에이전트가 한 번 봤다. 지적 16건 중 **높음 3건·보통 6건을 고쳤다**(아래 "검토에서 고친 것").

| 날짜 묶음 | 받은 순서대로 같은 날끼리 묶고 머리글은 `오늘`·`어제`·`10월 13일 화요일` | 알림함은 날짜가 뼈대다. 쪽을 이어 받아도 묶음이 자연히 이어진다 |
| 읽은 줄 | "안 읽은 알림" 목록에서도 바로 사라지지 않는다(다시 받을 때 빠진다) | 누른 줄이 눈앞에서 사라지면 무엇을 눌렀는지 놓친다 |

| 모두 읽음 | 받아 둔 쪽만 보지 않고 **서버가 센 수**로 맞춘다. 목록을 받기 전에는 단추를 막는다 | 첫 쪽 20건이 다 읽음이어도 아래 쪽에 안 읽은 알림이 남아 있을 수 있다. 목록을 받기 전에는 실패했을 때 되돌릴 값이 없다 |

| 목 모드 | 그대로 둔다(6건, 쪽 없음). 목 저장소만 새 모양으로 바꿨다 | 상태 미리보기와 로그인 없는 화면 확인이 계속 된다. CI의 web 빌드도 목 모드다 |

## 합친 뒤 확인

실제 모드(`NEXT_PUBLIC_USE_MOCKS=false`)로 web을 띄우고 로그인한 다음, 알림이 있어야 보인다. 없으면 먼저 예약·발송을 한 번 돌린다(앞 PR의 작업 두 개, `INTERNAL_API_KEY`가 `api/.env`에 있다).

```powershell
$env:KEY = Read-Host "INTERNAL_API_KEY"
curl.exe -s -X POST -H "X-Internal-Key: $env:KEY" http://localhost:8000/api/v1/internal/jobs/schedule-notifications
curl.exe -s -X POST -H "X-Internal-Key: $env:KEY" http://localhost:8000/api/v1/internal/jobs/send-notifications
```

알림 시각이 KST 09:00이라 **오늘 예약한 알림은 내일 아침에 보인다**. 지금 바로 보고 싶으면 시험용 DB에서 `update notifications set scheduled_at = now() - interval '1 hour', status = 'succeeded', sent_at = now() where user_id = (select id from profiles limit 1);`로 시각만 당겨 보면 된다(실제 DB에서는 하지 않는다).

1. **배지:** 헤더 종 단추에 안 읽은 수가 빨간 동그라미로 붙는다. 어느 화면에서든 같다.
2. **패널:** 종을 누르면 오른쪽에서 패널이 열리고 최근 20건이 최신순으로 뜬다. 안 읽은 줄은 연한 주색 바탕이다. 보낼 때가 안 된 알림은 보이지 않는다.
3. **누르면 이동:** 마감 임박 알림을 누르면 그 공고 상세로 가고 배지가 1 줄어든다. 새로 고쳐도 그대로다. 정보 필요 알림을 누르면 주소에 `?focus=profile_input`이 붙어 정보 입력창이 열린다.
4. **전체 목록:** 패널 아래 "모든 알림 확인하기"를 누르면 `/notifications`가 열린다. 날짜 묶음(오늘·어제·10월 13일 화요일)으로 나뉘고, 21건 이상이면 아래에 "더 보기"가 있다.
5. **필터:** "안 읽은 알림" 탭을 누르면 안 읽은 것만 남는다(읽은 줄은 다시 받을 때 빠진다). 탭을 바꾸면 처음 쪽부터 받는다.
6. **모두 읽음:** 누르면 안내가 뜨고 배지가 0이 된다. 새로 고쳐도 0이다.
7. **키보드:** 패널이 닫혀 있을 때 탭으로 돌아다녀도 보이지 않는 단추에 초점이 가지 않는다. 종 단추에서 Enter로 열린다.
8. **좁은 화면:** 390px에서 가로 스크롤이 생기지 않는다.

### 처음에 놓친 되돌림 두 가지

- **"모두 읽음이 받아 둔 쪽만 본다"**: 처음에는 안전장치(`if (unread === 0) return true;`)를 **지우는** 변형을 만들었는데, 그건 요청만 한 번 더 보내고 결과는 같아서 잡히지 않는 게 맞았다. 변형을 실제 버그 모양(`받아 둔 쪽에 안 읽은 알림이 없으면 아무것도 안 함`)으로 다시 만들었더니 "첫 쪽이 다 읽음" 단계가 잡았다.
- **"버린 응답에서 더 보기 단추를 안 되살린다"**: 검토 지적을 고치면서 같은 일을 두 군데서 했다(응답 처리와 목록 다시 받기). 뒤쪽만 있어도 멈추지 않으므로 응답 처리 쪽을 지우고, 남은 한 줄을 변형해 잡히는지 다시 확인했다.

### 검토에서 고친 것

| 지적 | 고친 것 |
| --- | --- |
| 다음 쪽 응답이 버려지면 `loadingMore`가 true로 굳어 "더 보기"가 죽는다 | 목록을 다시 받을 때 풀어 준다. E2E로 재현해 두었다(실패 7단계) |
| 목록을 받기 전 "모두 읽음"이 실패하면 배지가 0으로 굳는다(되돌릴 값이 `null`) | 목록을 받기 전에는 단추를 막고, 훅도 그때는 부르지 않는다 |
| 필터를 바꿀 때 앞 목록·cursor를 안 버려 스스로 422를 만든다 | 필터가 바뀌면 목록과 cursor를 먼저 버린다 |
| 알림함 화면에 목록이 두 벌(화면·패널)이라 숫자가 어긋난다 | 부제도 배지와 같은 숫자(한 군데 값)를 쓰게 했다. 줄 표시가 두 벌인 것은 남은 것에 적었다 |
| 오류 안내의 단추가 오류를 못 고친다("알림함 열기"·"홈으로 가기") | 훅이 `reload`를 내보내고 둘 다 "다시 시도"로 바꿨다 |
| 422를 `code`만 보고 분기해 모든 `VALIDATION_FAILED`를 cursor 문제로 취급한다 | `fieldErrors(error).cursor`가 있을 때만 되감는다(레포 규칙대로 `fieldErrors` 사용). 아닌 422는 그대로 알린다 |
| 닫힌 패널의 단추 셋이 탭 순서에 남는다(`aria-hidden` 안의 초점) | `inert`를 붙이고 종 단추에 `aria-expanded`·`aria-controls`·`aria-haspopup`을 달았다 |
| 안 읽음과 종류가 색으로만 전달된다 | 안 읽은 줄에 화면 읽기 프로그램용 "안 읽음" 글을 넣었다 |
| 움직임 줄이기 설정이 `animation-delay`를 못 지워 마지막 줄이 1.3초간 안 보인다 | `globals.css`의 줄이기 규칙에 `animation-delay: 0ms`를 더하고, 시간차도 아홉째 줄에서 멈춘다 |

고치지 않은 지적은 "남은 것"에 적었다. `/me`와 알림함의 기준 시각이 다른 것, 알림 종류 끄기가 P1인 것, Escape로 패널 닫기(레포 `Modal`도 없다), 읽은 줄이 안 읽은 목록에 남는 것은 **일부러 그렇게 둔 것**이라 검토에 미리 알려 두고 지적에서 뺐다.

## 남은 것

- **줄을 눌러 이동한 뒤 읽음 저장이 실패하면** 그 자리에서 알리지 못한다(화면이 이미 바뀌었다). 배지가 1 적게 남고, 패널을 다시 열거나 새로 고치면 서버 수로 맞는다. 실패를 끝까지 따라가려면 배지·목록을 화면 밖 한 군데(스토어)에 둬야 해서 이번에는 두지 않았다.
- **알림함 화면에서 헤더 패널을 열면** 같은 목록을 두 벌 들고 있다. 한쪽에서 읽은 줄이 다른 쪽에는 안 읽음으로 보인다(배지와 부제는 한 숫자를 쓴다). 새로 고치면 맞는다.
- **알림 종류 끄기**는 P1(`GET`·`PATCH /me/settings`)이라 설정 화면에서 아직 못 바꾼다. 서버 배치는 이미 끈 종류를 건너뛴다.
- **목 데이터에 `link`가 `null`인 알림이 없다.** 갈 곳 없는 알림 경로는 실제 모드 E2E로만 확인했다.
- **Escape로 패널 닫기**가 없다. 레포 `Modal`도 없어서 함께 두었다. 넣을 때 같이 넣는 게 낫다.
- `/me`의 안 읽은 수는 DB `now()`로 세고 알림함은 주입된 시각으로 센다(앞 PR의 남은 것 그대로). 실제 운영에서는 같다.
- **`task_due`와 LMS 알림 종류**는 아직 서버가 만들지 않는다. 점 색과 이동 경로(과제·자료·공지 탭, 플래너)는 넣어 뒀으니 서버가 만들기 시작하면 화면은 그대로 쓴다.
- **실제 웹 푸시(F-33)**는 다음 PR이다. 서비스 워커와 구독 저장이 붙어도 이 화면은 그대로다(푸시를 못 받는 환경의 대체 수단이 알림함이다).

```ts
import type { AppNotification } from "@/types/api";
import type { Route } from "@/types/route";

// 알림을 누르면 갈 곳 (API 명세 10장). 갈 곳이 없는 알림(link: null)은 눌러도 읽음 처리만 한다
export default function notificationRoute(notification: AppNotification): Route | null {
  const link = notification.link;
  if (!link) return null;
  if (link.type === "opportunity") {
    return { name: "opportunity", id: link.id, focus: link.focus ?? undefined };
  }
  if (link.type === "planner_task") return { name: "planner" };
  // lms_* 알림의 link.id는 과제·자료·공지 ID라서 과목 이동에는 course_id를 쓴다
  const courseId = link.course_id;
  if (!courseId) return { name: "academics" };
  if (link.type === "lms_module_item") {
    return { name: "course", id: courseId, tab: "materials" };
  }
  if (link.type === "lms_announcement") {
    return { name: "course", id: courseId, tab: "announcements" };
  }
  return { name: "course", id: courseId, tab: "assignments" };
}
```

#### `web/src/lib/useNotifications.ts`

```ts
import { useCallback, useEffect, useRef, useState } from "react";
import {
  errorMessage,
  fieldErrors,
  getNotifications,
  markAllNotificationsRead,
  markNotificationRead,
  nowIso,
} from "@/api/client";
import type { AppNotification } from "@/types/api";

// 알림함 목록 상태. 헤더 패널(열릴 때만)과 전체 목록 화면이 각각 하나씩 쓴다.
// 읽음 처리는 응답을 기다리지 않고 먼저 화면에 반영하고, 저장하지 못하면 되돌린다(F-45와 같은 방식).
interface Options {
  enabled?: boolean; // 패널은 열려 있을 때만 받는다
  unreadOnly?: boolean;
}

export interface NotificationsState {
  items: AppNotification[];
  unread: number | null; // 아직 목록을 받지 못했으면 null (헤더는 내 정보의 수를 쓴다)
  loading: boolean;
  error: string | null;
  hasMore: boolean;
  loadingMore: boolean;
  reload: () => void;
  loadMore: () => void;
  read: (notification: AppNotification) => Promise<boolean>;
  readAll: () => Promise<boolean>;
}

export default function useNotifications({
  enabled = true,
  unreadOnly = false,
}: Options = {}): NotificationsState {
  const [items, setItems] = useState<AppNotification[]>([]);
  const [unread, setUnread] = useState<number | null>(null);
  const [cursor, setCursor] = useState<string | null>(null);
  const [loading, setLoading] = useState(false);
  const [loadingMore, setLoadingMore] = useState(false);
  const [error, setError] = useState<string | null>(null);
  const [round, setRound] = useState(0);
  const latest = useRef(0); // 늦게 온 응답은 버린다
  const shown = useRef(unreadOnly); // 지금 들고 있는 목록이 어느 필터의 것인지

  // 첫 쪽. 다시 받는 동안 이미 받은 알림은 그대로 둬서 패널을 다시 열 때 빈 화면이 보이지 않게 한다
  useEffect(() => {
    if (!enabled) return;
    const token = (latest.current += 1);
    // 필터가 바뀌면 앞 필터의 목록과 cursor를 먼저 버린다(옛 cursor로 다음 쪽을 부르면 422다)
    if (shown.current !== unreadOnly) {
      shown.current = unreadOnly;
      setItems([]);
      setCursor(null);
    }
    setLoading(true);
    setError(null);
    // 다음 쪽을 받던 중에 필터가 바뀌면 그 응답을 버린다. 여기서 풀어 주지 않으면 "더 보기"가 멈춘다
    setLoadingMore(false);
    getNotifications({ unreadOnly })
      .then((page) => {
        if (token !== latest.current) return;
        setItems(page.items);
        setUnread(page.unread_count);
        setCursor(page.next_cursor);
        setLoading(false);
      })
      .catch((cause: unknown) => {
        if (token !== latest.current) return;
        setError(errorMessage(cause, "알림을 불러오지 못했어요."));
        setLoading(false);
      });
  }, [enabled, unreadOnly, round]);

  const reload = useCallback(() => setRound((value) => value + 1), []);

  const loadMore = useCallback(() => {
    if (!cursor || loadingMore) return;
    const token = latest.current;
    setLoadingMore(true);
    getNotifications({ unreadOnly, cursor })
      .then((page) => {
        if (token !== latest.current) return;
        setLoadingMore(false);
        setItems((current) => [...current, ...page.items]);
        setUnread(page.unread_count);
        setCursor(page.next_cursor);
        setError(null);
      })
      .catch((cause: unknown) => {
        if (token !== latest.current) return;
        setLoadingMore(false);
        // 조건이 바뀐 목록의 cursor는 details.fields.cursor가 있는 422다. 처음부터 다시 받는다
        if (fieldErrors(cause).cursor) {
          setCursor(null);
          reload();
          return;
        }
        setError(errorMessage(cause, "알림을 더 불러오지 못했어요."));
      });
  }, [cursor, loadingMore, reload, unreadOnly]);

  // 읽음 처리한 알림은 "안 읽은 알림만" 목록에서도 바로 사라지지 않는다(누른 자리가 그대로 보여야 한다)
  const read = useCallback(
    async (notification: AppNotification) => {
      if (notification.read_at !== null) return true;
      const before = unread;
      mark(setItems, [notification.id], nowIso());
      setUnread(before === null ? null : Math.max(0, before - 1));
      try {
        setUnread(await markNotificationRead(notification.id));
        return true;
      } catch {
        mark(setItems, [notification.id], null);
        setUnread(before);
        return false;
      }
    },
    [unread],
  );

  // 받아 둔 쪽에 안 읽은 알림이 없어도 아래 쪽에 남아 있을 수 있어 전체 읽음은 서버가 센 수로 맞춘다.
  // 목록을 받기 전(unread === null)에는 되돌릴 수가 없어 부르지 않는다(부르는 쪽도 단추를 막는다)
  const readAll = useCallback(async () => {
    if (unread === null || unread === 0) return true;
    const ids = items.filter((item) => item.read_at === null).map((item) => item.id);
    const before = unread;
    mark(setItems, ids, nowIso());
    setUnread(0);
    try {
      setUnread(await markAllNotificationsRead());
      return true;
    } catch {
      mark(setItems, ids, null);
      setUnread(before);
      return false;
    }
  }, [items, unread]);

  return {
    items,
    unread,
    loading,
    error,
    hasMore: cursor !== null,
    loadingMore,
    reload,
    loadMore,
    read,
    readAll,
  };
}

type SetItems = (update: (current: AppNotification[]) => AppNotification[]) => void;

function mark(setItems: SetItems, ids: string[], readAt: string | null): void {
  setItems((current) =>
    current.map((item) => (ids.includes(item.id) ? { ...item, read_at: readAt } : item)),
  );
}
```

```tsx
function shiftDay(dateKey: string, days: number): string {
  return getKstDateKey(new Date(new Date(`${dateKey}T00:00:00+09:00`).getTime() + days * 86_400_000));
}

function dayLabel(dateKey: string, today: string): string {
  if (dateKey === today) return "오늘";
  if (dateKey === shiftDay(today, -1)) return "어제";
  return formatKstLongDate(dateKey);

    if (last?.key === key) last.items.push(item);
    else groups.push({ key, label: dayLabel(key, today), items: [item] });
```

```ts
// Make의 상태 기반 Route를 Next.js URL로 바꾼다. 화면 코드는 navigate(route)를 그대로 쓴다.
export function routeToHref(route: Route): string {
  switch (route.name) {
    case "home":
      return "/";
    case "opportunity":
      return `/opportunities/${encodeURIComponent(route.id)}${route.focus ? `?focus=${route.focus}` : ""}`;
    case "planner":
      return "/planner";
    case "academics":
      return "/academics";
    case "course":
      return `/academics/${encodeURIComponent(route.id)}${route.tab ? `?tab=${route.tab}` : ""}`;
    case "upload":
      return "/upload";
    case "notifications":
      return "/notifications";
    case "settings":
      return "/settings";
    case "onboarding":
      return "/onboarding";
  }
}

// 사이드바 활성 표시용. 과목 상세는 학업 메뉴를 켠다.
export function pathnameToRoute(pathname: string): Route {
  const [, first, second] = pathname.split("/");
  if (first === "opportunities" && second) return { name: "opportunity", id: decodeURIComponent(second) };
  if (first === "academics") return { name: "academics" };
  if (first === "planner") return { name: "planner" };
  if (first === "upload") return { name: "upload" };
  if (first === "notifications") return { name: "notifications" };
  if (first === "settings") return { name: "settings" };
  if (first === "onboarding") return { name: "onboarding" };
  return { name: "home" };
}
```

```ts
export function getFeed(
  categories: Category[] | null,
  sort: "deadline" | "recent",
  includeNotInterested: boolean,
): Promise<FeedResponse> {
  if (getDevScenario() === "empty_feed") {
    return respond({ items: [], next_cursor: null, counts: countItems([]) });
  }
  const shown = opportunities.filter((item) => item.my_mark !== "not_interested");
  const items = (includeNotInterested ? opportunities : shown).filter((item) => !categories || categories.includes(item.category));
  items.sort((a, b) =>
    sort === "deadline"
      ? (a.d_day ?? Number.MAX_SAFE_INTEGER) - (b.d_day ?? Number.MAX_SAFE_INTEGER)
      : // 실제 API는 등록 최신순이다. 목데이터에는 등록 시각이 없어 새 공고만 앞으로 보낸다
        Number(b.is_new) - Number(a.is_new),
  );
  return respond({ items, next_cursor: null, counts: countItems(shown) });
}
```

```ts
export function listStoredNotifications(unreadOnly: boolean): NotificationList {
  const items = notificationState
    .filter((item) => !unreadOnly || item.read_at === null)
    .map((item) => ({ ...item }));
  return { items, unread_count: countUnread(), next_cursor: null };
}

export function readStoredNotifications(ids: string[], readAt: string): number {
  notificationState.forEach((notification) => {
    if (ids.includes(notification.id) && notification.read_at === null) {
      notification.read_at = readAt;
    }
  });
  return countUnread();
}

export function readAllStoredNotifications(readAt: string): number {
  notificationState.forEach((notification) => {
    if (notification.read_at === null) notification.read_at = readAt;
  });
  return countUnread();
}

function countUnread(): number {
  return notificationState.filter((item) => item.read_at === null).length;
```

```tsx
// 알림 목록은 패널을 열 때 받고(useNotifications), 여기서는 배지 숫자만 들고 있는다
const MeContext = createContext<Me | null>(null);
export const useMe = () => useContext(MeContext);

export default function AppFrame({ children }: { children: ReactNode }) {
  const pathname = usePathname();
  const router = useRouter();
  const navigate = useAppNavigate();
  const [revision, setRevision] = useState(0);
  const [unread, setUnread] = useState<number | null>(null);
  const meRequest = useAsyncData(getMe, [revision]);
  const openRecorded = useRef(false);

  useEffect(() => {
    setUnread(null);
  }, [revision]);

  useEffect(() => {
    if (meRequest.data && !meRequest.data.consented) router.replace("/onboarding");
  }, [meRequest.data, router]);

  useEffect(() => {
    if (!meRequest.data?.consented || openRecorded.current) return;
    openRecorded.current = true;
    recordEvent("app_open");
  }, [meRequest.data]);

  return (
    <MeContext.Provider value={meRequest.data}>
      <AppShell
        route={pathnameToRoute(pathname)}
        unreadNotifications={unread ?? meRequest.data?.unread_notifications ?? 0}
        setUnreadNotifications={setUnread}
        navigate={navigate}
      >
        <Fragment key={revision}>{children}</Fragment>
      </AppShell>
      {showDevTools && <StatusPreview onChange={() => setRevision((value) => value + 1)} />}

  );
```
