# 판정 엔진 규칙 (S1-3)

> 📝 2026-10-07 · 기준: PRD v0.9 5-3, ERD v0.9 5장, API 명세 v0.4 5장 · 구현: `판정엔진_구현.md` (`api/app/eligibility/`, 테스트 85개 통과)
>
> 판정 엔진이 지키는 규칙 전체다. 요건 추출(S1-4)은 4장의 값 모양대로 요건을 저장하고, 공고 상세 API(S1-6)는 7장 문구를 그대로 내려준다. PRD 5-3의 판정 규칙 절은 이 문서를 가리키는 한 줄로 줄이고, PRD 14장 미결 "판정 세부 규칙"은 0장이 확정되면 닫는다.

---

## 0. 이번에 정한 것

PRD 14장의 미결 "판정 세부 규칙"과 구현하면서 생긴 질문을 아래처럼 정했고, 2026-10-07에 팀이 모두 확정했다. 나중에 바꾸게 되면 구현에서 한 곳과 그 테스트만 고치면 된다.

| # | 항목 | 정한 규칙 | 이유 |
| --- | --- | --- | --- |
| 1 | 병역 연장 상한 | 공고에 최대 개월이 적혀 있으면 그만큼만 늘린다. 적혀 있지 않으면 복무 개월 전부를 더한다 | 복무 기간은 대부분 18–21개월이라 흔한 상한(3년)에 거의 닿지 않는다. 넉넉하게 잡으면 오판정이 '지원 가능' 쪽으로만 생긴다 |
| 2 | 병역 복무 개월을 모를 때 | 늘리지 않아도 통과하면 지원 가능, 최대로 늘려도 넘으면 지원 어려움, 그 사이면 정보 필요(병역 복무 개월) | 판정이 바뀔 수 있을 때만 묻는다 |
| 3 | 평점 만점이 다를 때 | 환산하지 않고 원문 확인 필요로 둔다. 요건 값에 만점이 없으면 4.5 만점으로 본다. 100점·백분위 조건도 마찬가지다 | 환산식(ERICA 백분위 환산 등)이 아직 없다. 환산식이 정해지면 이 규칙만 바꾼다 |
| 4 | 이수 학기 | 요건은 마친 학기 수 기준으로 저장한다. "8학기 이내 재학"은 7 이하, "N학기 이상 이수"는 N 이상이다. 현재 학기를 세는지 애매하면 모호 조건으로 둔다 | 프로필 값이 마친 학기 수다 |
| 5 | 학년 | 프로필 값 그대로 비교한다. 기준일에 맞춰 진급을 계산하지 않는다 | 학년은 학기 초에만 바뀌고 진급 시점이 학교마다 다르다 |
| 6 | 만 나이 | 출생일을 넣어 센다. 그 달에 같은 날짜가 없으면 다음 달 1일에 나이가 오른다(2월 29일생은 평년에 3월 1일) | 민법의 기간 계산 |
| 7 | 지역 이름 | 시도는 정식 이름 17개로 맞춘다(서울·경기·강원도·전라북도 같은 별칭 포함). 요건 값은 "시도" 또는 "시도 시군구"로 저장한다. 시도 없이 시군구만 있으면 모호 조건이다 | "중구"·"동구" 같은 이름은 여러 시도에 있다 |
| 8 | 학과 이름이 목록과 다를 때 | 요건 값이 학과 목록에 없는 이름이면 원문 확인 필요로 둔다. 목록에 있는 이름인데 해당하지 않을 때만 지원 어려움이다 | 이름이 달라서 생긴 불일치를 지원 어려움으로 내지 않는다 |
| 9 | 요건이 없는 공고 | 지원 가능. 요건 추출에 실패한 공고는 판정하지 않는다(호출하는 쪽 책임) | 자격 제한이 없는 공고가 실제로 있다 |
| 10 | 정보 필요 입력창 | 나이 조건이 비면 생년월일을 묻는다. 생년월일은 있는데 병역 연장 때문에 모를 때는 병역 복무 개월을 묻는다. 소득 항목은 선택 동의를 먼저 받는다 | 빠진 항목은 요건 항목(age 등)이라 물어볼 칸을 따로 정한다 |

## 1. 입력과 출력

판정 함수는 `check_eligibility(requirements, profile, *, basis_date, departments)` 하나다. DB·LLM·현재 시각을 쓰지 않는 순수 함수라서 입력이 같으면 결과도 늘 같다.

| 입력 | 내용 |
| --- | --- |
| requirements | 공고의 requirements 행 (clause_no, field, operator, value, basis, is_ambiguous, evidence_text) |
| profile | 판정용 프로필 항목과 평점 만점 |
| basis_date | 판정 기준일 (8장) |
| departments | 학과 목록 (학과·단과대학·계열) |

| 출력 | 내용 |
| --- | --- |
| status | eligible · ineligible · undetermined |
| display_status | eligible · missing_info · needs_review · ineligible (화면 라벨 4종) |
| clauses | 묶음별 결과와 조건 수 |
| conditions | 조건별 결과, 모름 이유, 비교에 쓴 내 값 |
| missing_fields | 입력하면 판정이 바뀔 수 있는 항목 |
| reason_text | 사유 한 줄 |

`storage_row()`가 eligibility_results에 넣을 값을 만든다. requirements_version은 호출하는 쪽이 공고의 값을 넣는다.

## 2. 판정 순서

1. 기준일을 정한다 (8장)
2. 조건마다 충족·불충족·모름을 낸다 (3·4장)
3. 묶음마다 결과를 낸다 (5장)
4. 공고 결과를 낸다 (5장)
5. 정보 필요 항목을 고른다 (6장)
6. 라벨과 사유 한 줄을 만든다 (6·7장)

---

## 3. 조건 결과

조건 결과는 충족(pass), 불충족(fail), 모름(unknown) 셋이다. 위에서부터 처음 맞는 줄로 정한다.

| 순서 | 상황 | 결과 | 모름 이유 |
| --- | --- | --- | --- |
| 1 | 항목이 other | 모름 | unsupported_field |
| 2 | is_ambiguous가 true | 모름 | ambiguous |
| 3 | 값 모양이 4장과 다름 (쓸 수 없는 연산자, 숫자가 아님, 목록이 아님, min이 max보다 큼 등) | 모름 | ambiguous |
| 4 | 기준이 다름 (실거주·출신 고교·보호자 주소 기준 지역, 만점이 다른 평점) | 모름 | basis_mismatch |
| 5 | 필요한 프로필 값이 없음 | 모름 | missing_profile |
| 6 | 비교 | 충족 또는 불충족 | — |

- 기준이 다른 조건은 프로필이 비어 있어도 묻지 않는다. 입력해도 판정할 수 없기 때문이다.
- 값 모양이 틀린 요건은 어떤 경우에도 불충족이 되지 않는다. 추출 오류가 '지원 어려움'으로 이어지지 않게 하기 위해서다.
- 숫자는 Decimal로 비교한다(3.00 = 3.0). 이상·이하·between은 경계를 포함한다.

## 4. 항목별 규칙

연산자는 eq(같음), neq(다름), in(목록 중 하나), not_in(목록에 없음), gte(이상), lte(이하), between(min 이상 max 이하, 한쪽만 있어도 됨)이다.

| 항목 | 프로필 값 | 연산자 | value 예 | basis |
| --- | --- | --- | --- | --- |
| department | 학과 (목록에서 고름) | eq·neq·in·not_in | `["소프트웨어융합대학"]` | department·college·field_group 중 하나 (필수) |
| grade | 학년 | 모두 | `4`, `[1, 2]`, `{"min": 2, "max": 4}` | 없음 |
| enrollment_status | 학적 상태 | eq·neq·in·not_in | `["enrolled", "on_leave"]` | 없음 |
| semesters_completed | 마친 학기 수 | 모두 | `7` | 없음 |
| credits_total · credits_last_semester | 이수학점 | 모두 | `12` | 없음 |
| gpa_total · gpa_last_semester | 평점, 평점 만점 | eq·gte·lte·between | `3.0`, `{"value": 80, "scale": 100}`, `{"min": 3.0, "max": 4.5, "scale": 4.5}` | 없음 |
| age | 생년월일, 병역 복무 개월 | gte·lte·between | `19`, `{"min": 19, "max": 34, "military_extension": true}` | 없음 |
| region | 시도, 시군구 (주민등록 주소) | eq·neq·in·not_in | `["경기도 안산시"]` | resident_registration·unspecified·actual_residence·high_school·guardian 중 하나 (필수) |
| income_bracket | 학자금 지원구간 (0–10) | 모두 | `8` | 없음 |
| median_income_pct | 기준 중위소득 % | 모두 | `150` | 없음 |
| welfare_status | none·near_poverty·basic_livelihood | eq·neq·in·not_in | `["basic_livelihood", "near_poverty"]` | 없음 |
| is_international | 외국인 유학생 여부 | eq·neq | `true` | 없음 |
| other | — | 모두 | `{"text": "봉사활동 20시간 이상"}` | 없음 |

학적 상태 값은 enrolled(재학), on_leave(휴학), deferred_graduation(졸업유예), graduated(졸업)이다.

### 4-1. 나이

- 만 N세가 되는 날은 출생일에서 12×N개월 뒤다. 그 달에 같은 날짜가 없으면 다음 달 1일이다.
- 하한(min): 기준일이 min세가 되는 날과 같거나 뒤면 충족이다.
- 상한(max): 기준일이 (max+1)세가 되는 날보다 앞이면 충족이다. 병역 연장이 있으면 그날에 연장 개월을 더한다.
- 연장 개월: `military_extension`이 true면 복무 개월 전부, `{"max_months": 36}`이면 복무 개월과 36 중 작은 값이다. 연장은 상한에만 붙는다.
- 복무 개월을 모르면 0장 2번대로 한다.

| 예 | 기준일 | 결과 |
| --- | --- | --- |
| 1991-10-16생, 만 19–34세 | 2026-10-15 | 충족 (만 34세 마지막 날) |
| 1991-10-15생, 만 19–34세 | 2026-10-15 | 불충족 (35번째 생일) |
| 2004-02-29생, 만 19세 이상 | 2023-02-28 / 2023-03-01 | 불충족 / 충족 |
| 1991-03-10생(만 35세), 34세 + 병역 연장, 복무 21개월 | 2026-10-15 | 충족 (2027-12-10 전까지) |
| 같은 사람, 복무 개월 미입력 | 2026-10-15 | 정보 필요 (병역 복무 개월) |
| 1985-01-01생, 34세 + 연장 최대 36개월, 복무 개월 미입력 | 2026-10-15 | 불충족 (최대로 늘려도 넘음) |

### 4-2. 거주지역

- 프로필 지역은 주민등록 주소다. 요건 기준이 resident_registration이나 unspecified(명시 없음)면 비교하고, actual_residence·high_school·guardian이면 모름(basis_mismatch)이다.
- 시도는 정식 이름 17개로 맞춘다. 받는 별칭은 서울·서울시, 부산·부산시, 대구·대구시, 인천·인천시, 광주, 대전·대전시, 울산·울산시, 세종·세종시, 경기, 강원·강원도, 충북, 충남, 전북·전라북도, 전남, 경북, 경남, 제주·제주도다. "광주시"는 경기도 광주시와 겹쳐서 받지 않는다.
- 시군구는 끝의 시·군·구를 떼고 비교한다("안산" = "안산시").

| 요건 값 | 내 주소 | 결과 |
| --- | --- | --- |
| 경기도 | 경기도 안산시 단원구 | 일치 |
| 경기도 안산시 | 경기도 안산시 단원구 | 일치 |
| 경기도 안산시 단원구 | 경기도 안산시 | 모름 (정보 필요: 거주지역) |
| 경기도 안산시 상록구 | 경기도 안산시 단원구 | 불일치 |
| 경기도 안산시 | 경기도 안성시 | 불일치 |
| 안산시 (시도 없음) | — | 모름 (원문 확인 필요) |

- in·eq: 하나라도 일치하면 충족이다. 일치하는 값이 없을 때 시도 없는 값이 있으면 모호, 요건이 더 구체적인 값이 있으면 정보 필요, 둘 다 아니면 불충족이다.
- not_in·neq: 하나라도 일치하면 불충족이다. 나머지는 in과 같은 순서로 정한다.

### 4-3. 학과

- basis가 비교 단위다. department는 학과, college는 단과대학, field_group은 계열로 비교하고, 프로필 학과로 학과 목록에서 단과대학과 계열을 찾는다.
- 요건 값이 그 단위의 목록 이름에 없으면(예: 요건은 "공과대학"인데 목록 이름은 다름) 모호 조건이다.
- 프로필 학과가 비었거나 목록에 없는 이름이면 정보 필요(학과)다.
- 학과 통폐합 이력은 다루지 않는다.

### 4-4. 평점

- 만점은 value의 `scale`로 적고, 없으면 4.5다.
- 요건 만점과 프로필 만점(gpa_scale, 기본 4.5)이 다르면 모름(basis_mismatch)이다.
- 학점 글자로 적힌 조건은 4.5 만점 값으로 저장한다(A0 4.0, B+ 3.5, B0 3.0). "B학점(80점)"처럼 100점 기준이 함께 적혀 있으면 100점 기준으로 저장하고, 환산식이 정해질 때까지 원문 확인 필요로 둔다.

### 4-5. 소득·수급

- 학자금 지원구간, 기준 중위소득 %, 수급 여부는 서로 바꿔 계산하지 않는다.
- 공고가 여러 기준을 "또는"으로 적었으면 같은 묶음에 넣는다. 그러면 사용자가 입력한 기준 하나만 맞아도 그 묶음은 충족이다.
- 공고가 쓴 기준을 사용자가 입력하지 않았으면 정보 필요다. 다른 소득 값이 있어도 그 값으로 대신 판정하지 않는다.
- "기초생활수급자 또는 차상위계층"은 `welfare_status in ["basic_livelihood", "near_poverty"]`이다.
- 소득·수급 값은 선택 동의가 있어야 저장된다(ERD v0.9). 그래서 정보 입력창에서 소득 항목을 물을 때는 선택 동의를 먼저 받는다.

### 4-6. 학년·학기·학적

- 학년은 0장 5번, 이수 학기는 0장 4번대로 한다.
- 학적 상태: "재학생"은 enrolled, "휴학생 포함"은 `in ["enrolled", "on_leave"]`, "졸업유예자 제외"는 `not_in ["deferred_graduation"]`이다.

### 4-7. 기타 조건과 모호 조건

- 프로필로 판정할 수 없는 조건(봉사 시간, 어학 성적, 면접 등)은 other로 저장하고 value에 `{"text": "원문 요약"}`을 넣는다. 결과는 늘 모름이다.
- 근거 문장이 원문에 없거나 해석이 갈리면 is_ambiguous를 true로 둔다. 그 조건은 모름이고, 프로필을 묻지 않는다.
- 모름 조건이 있어도 같은 묶음의 다른 조건이 충족이면 그 묶음은 충족이다.

## 5. 묶음과 공고

- 묶음: 충족한 조건이 하나라도 있으면 충족, 모두 불충족이면 불충족, 그 밖은 모름이다.
- 공고: 불충족 묶음이 하나라도 있으면 지원 어려움, 모든 묶음이 충족이면 지원 가능, 그 밖은 판정 불가다.
- 요건이 하나도 없으면 지원 가능이다.

PRD 5-3 예시가 그대로 테스트에 들어 있다.

| 공고 | 프로필 | 결과 | 라벨 |
| --- | --- | --- | --- |
| 평점 3.0 이상 또는 8구간 이하 | 평점 미입력, 6구간 | 묶음 충족 | 지원 가능 |
| 〃 | 평점 2.8, 구간 미입력 | 묶음 모름 | 정보 필요 (학자금 지원구간) |
| 〃 | 평점 2.8, 9구간 | 묶음 불충족 | 지원 어려움 |
| 12학점 이상 (단, 4학년 9학점) | 4학년, 10학점 | 두 묶음 충족 | 지원 가능 |
| 〃 | 3학년, 10학점 | 묶음 1 불충족 | 지원 어려움 |
| 〃 | 학년 미입력, 13학점 | 두 묶음 충족 | 지원 가능 |
| 〃 | 학년 미입력, 10학점 | 묶음 1 모름, 묶음 2 충족 | 정보 필요 (학년) |

"12학점 이상 (단, 4학년 9학점)"은 묶음 1 = (4학년 또는 12학점 이상), 묶음 2 = (4학년이 아님 또는 9학점 이상)으로 저장한다.

## 6. 정보 필요 항목과 라벨

- missing_fields는 판정 불가일 때만 채운다. 결과가 모름인 묶음에서, 프로필이 비어 모름이 된 조건의 항목만 넣는다(요건 순서, 중복 없음). 이미 충족한 묶음의 빈 항목은 묻지 않는다. 지원 가능이나 지원 어려움이면 비운다.
- 라벨은 eligible이면 지원 가능, ineligible이면 지원 어려움이다. undetermined는 missing_fields가 있으면 정보 필요, 없으면 원문 확인 필요다.
- 두 원인이 같이 있으면 입력하면 바뀔 수 있는 정보 필요를 먼저 보여준다. 입력 뒤 다시 판정해서 라벨을 바꾼다.
- 정보 입력창의 칸은 0장 10번을 따른다.

## 8. 기준일과 다시 판정하는 때

- 기준일은 공고의 eligibility_basis_date, 없으면 신청 마감일의 KST 날짜, 그것도 없으면 판정하는 날(KST)이다. 마감이 2026-10-15 23:59 KST면 기준일은 10/15다.
- 엔진은 현재 시각을 읽지 않는다. 호출하는 쪽이 KST 오늘 날짜를 넘기고, 테스트는 이 값을 고정한다.
- KST는 +09:00 고정 오프셋으로 둔다. 서머타임이 없어서 정확하고, Windows에서도 tzdata 없이 돈다.

다시 판정하는 때(호출하는 쪽에서 한다):

| 바뀐 것 | 다시 판정할 범위 |
| --- | --- |
| 프로필 저장, 소득·수급 동의 철회 | 그 사용자의 활성 공고 전체 |
| 요건 재추출 (requirements_version 증가) | 그 공고 × 모든 사용자 |
| 학과 목록 변경 | 학과 조건이 있는 공고 |
| 날짜 (매일 새벽 배치) | 기준일과 마감일이 모두 없고 나이 조건이 있는 공고. 기준일이 오늘이라 나이가 바뀔 수 있다 |

요건 추출에 실패한 공고는 판정 결과를 만들지 않는다.

## 10. 요건 추출(S1-4)에 넘길 것

- `requirement_problem(req)`: 판정할 수 있는 모양이면 None, 아니면 고칠 점을 한국어 한 줄로 돌려준다. 추출 결과를 스키마로 검증한 뒤 이걸 돌리고, 문제가 있으면 메시지를 모델에 돌려주고 1회 재시도한다(PRD 6장).
- `ALLOWED_OPERATORS`: 항목별 연산자 목록이다. 추출 스키마의 enum으로 쓴다.

추출 프롬프트에 넣을 규칙:

1. 조건 하나가 행 하나다. "또는"은 같은 clause_no, "그리고"는 다른 clause_no로 둔다.
2. "단, …은 …" 같은 예외는 묶음 두 개로 푼다(5장 예).
3. 지역은 "시도" 또는 "시도 시군구"로 쓰고 basis를 꼭 정한다. 기준이 적혀 있지 않으면 unspecified다.
4. 학과 조건은 학과 목록의 이름으로 쓰고 basis를 정한다. 목록에 없는 이름이면 원문 그대로 쓰고 is_ambiguous를 true로 둔다.
5. 평점은 만점이 4.5가 아니면 scale을 적는다. 학점 글자는 4.5 만점 값으로 쓴다.
6. 나이는 만 나이로 쓴다. 병역 연장 문구가 있으면 military_extension을 넣고, 최대치가 적혀 있으면 max_months로 쓴다.
7. 이수 학기는 마친 학기 수 기준이다(0장 4번).
8. 프로필로 판정할 수 없는 조건은 other로 두고 value에 `{"text": …}`를 넣는다.
9. 근거 문장(evidence_text)은 원문에서 그대로 복사한다.
