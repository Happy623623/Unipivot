# 데모 리허설 체크리스트

> 📝 기준: PRD v0.9 4장(핵심 흐름)·8장(테스트 시나리오)·11장(W11 데모)·12장(리스크) · README "데모" 절
>
> 데모 흐름(무엇을 어떤 순서로 보여 줄지)은 README "데모" 절에 있다. 이 문서는 그 흐름을 **그날 그대로 돌리기 위한 준비**다.
> 리허설을 한 번 할 때마다 맨 아래 "리허설 기록"에 한 줄을 더한다.

## 원칙

- **데모 전용 Google 계정**으로 한다. LearningX는 데모 전용 계정이 없어서 팀원 계정을 쓴다 — 그 팀원의 동의를 받고, 과목 화면에 보이는 것(과목·교수 이름)을 미리 확인한다. 포털 강의계획서 페이지(이름·학번이 보인다)는 화면에 띄우지 않는다(PRD 11장 마스킹).
- 화면에 키·토큰·`.env`·터미널의 비밀 값이 보이면 안 된다. 개발자 도구는 닫는다.
- 모델을 부르는 단계(요건 추출·포스터·계획서·강의자료 요약)는 수십 초 걸린다. **그 자리에서 돌릴 것과 미리 돌려 둘 것을 다른 자료로** 준비한다(같은 공고·포스터를 다시 쓰면 "이미 등록함"이나 중복 화면이 뜬다). 처리 과정은 끝난 실행도 그대로 보여 준다.
- 네트워크가 안 될 때의 백업은 **데모 노트북 안에서만** 돈다: 노트북에서 목 모드로 빌드한 화면(`NEXT_PUBLIC_USE_MOCKS=true` — 빌드할 때 정해지므로 따로 빌드해 둔다)과, 노트북의 로컬 시험 DB에서 돌리는 `uv run python -m app.eval.cli`(api 폴더, 녹화한 응답). 배포한 목 모드 주소는 인터넷이 있어야 해서 백업이 아니다.

## D-7 (일주일 전)

- [ ] Google 앱 게시 상태를 본다. 프로덕션(미검증)이면 캘린더 연결 때 뜨는 "Google에서 확인하지 않은 앱" 화면을 넘기는 것도 리허설한다(`docs/배포_절차.md` 5장 '앱 게시'). 아직 테스트면 데모 전용 Google 계정이 **테스트 사용자**에 있다
- [ ] LearningX 토큰을 쓸 팀원의 동의를 받았고, 토큰 만료일이 데모 날보다 뒤다(LearningX의 토큰 화면에서 본다 — 앱에는 끝 4자리와 마지막 동기화만 보인다)
- [ ] Gemini를 부르는 서버의 체험 크레딧이 남아 있고 만료일(가입 후 90일)이 데모 날보다 뒤다(docs/LLM_모델_선정.md)
- [ ] Supabase 프로젝트가 켜져 있다(대시보드에서 열어 본다). 무료 플랜이면 오래 쓰지 않은 프로젝트가 멈출 수 있다
- [ ] 배포한 api를 **데모 기간**으로 바꾼다: 최소 인스턴스 1(`docs/배포_절차.md` 8장). 그래야 정기 작업이 제때 돌고 첫 화면이 늦지 않다. 크레딧이 하루 2달러쯤(추정) 빠진다
- [ ] 배포 서버에 `GOOGLE_OAUTH_CLIENT_ID`·`GOOGLE_OAUTH_CLIENT_SECRET`이 있다(배포 미리보기에 그 알림이 없다). 없으면 캘린더 권한이 55분 뒤 끊겨 리허설 중 다시 연결하라고 뜬다(`docs/배포_절차.md` 5장 "캘린더 권한 유지")
- [ ] 보여 줄 자료가 모두 있다. 남의 개인정보가 없는 것만 쓴다. 그 자리에서 돌릴 것과 미리 돌려 둘 것을 **한 벌씩** 준비한다:
  - 학교 장학 공지 저장 폴더 — 지원 가능·지원 어려움·정보 필요가 하나씩, 요건이 모호한 공지 하나(원문 확인 필요), 첨부에만 요건이 있는 공지 하나, 그리고 마감일을 캘린더에 넣어 본 적 없는 공지 하나(캘린더 리허설용)
  - 포스터 사진(팀이 만든 것이나 공개 포스터), 흐릿한 사진 1장(저신뢰도 배지용)
  - 강의계획서 PDF(LMS 과목의 것)
  - 글자가 있는 강의 PDF(10~30쪽, 요약용), 아주 긴 PDF 1개(상한 안내용)
- [ ] 데모 계정의 프로필을 정했다 — 위 공지에서 네 라벨(지원 가능·정보 필요·원문 확인 필요·지원 어려움)이 다 나오게. 정한 값은 이 문서가 아니라 팀 메모에 둔다
- [ ] 노트북의 로컬 시험 DB에서 `uv run python -m app.eval.cli`가 전부 통과한다(지표 백업)
- [ ] 백업 영상: 전체 흐름을 한 번 녹화해 둔다(마스킹 확인 후)

## D-1 (전날)

- [ ] **데모 계정을 처음 상태로**: 앱에는 준비 일정·포스터를 한꺼번에 지우는 기능이 없으니 탈퇴하고 다시 가입한다(탈퇴는 데이터를 지우고 Google 권한도 끊는다). 탈퇴 **전에** 공고 상세의 "캘린더에서 빼기"로 넣어 둔 마감일을 뺀다 — 아니면 Google 캘린더에 예전 일정이 남아 다시 넣은 일정과 겹쳐 보인다(남았으면 Google 캘린더에서 직접 지운다). 다시 가입한 뒤 LearningX·캘린더·웹 푸시를 다시 연결한다
- [ ] **Google 캘린더 재연결 리허설**(처음 상태로 돌린 **뒤**): 캘린더를 연결하고, 마감일을 넣어 본 적 없는 공지로 준비하기 → 마감일 등록이 되는지 본다(이미 넣은 마감일은 Google을 부르지 않고 저장된 일정을 그대로 돌려줘서 확인이 안 된다). 테스트 상태의 refresh token은 7일 뒤 만료된다(PRD 12장)
- [ ] Supabase 프로젝트가 켜져 있다(D-7에 이어 한 번 더)
- [ ] 배포한 서버에서 정기 작업이 돈다(배포 명령이 `SCHEDULER_ENABLED=true`로 올린다. 온통청년 수집은 `YOUTH_API_KEY`도 필요하고, 최소 인스턴스가 1이어야 제때 돈다): 온통청년 수집(04:00)은 `agent_runs`에, 공고 알림 예약(08:30)은 `notifications` 표나 서버 로그(`docs/배포_절차.md` 6장)에 오늘 것이 있는지 본다. 로컬 api의 `SCHEDULER_ENABLED`는 false로 둔다(같은 DB에 두 번 돈다)
- [ ] 저장한 학교 공지를 넣는다: `uv run python -m app.crawl.cli import <공지 폴더…>` → 홈에 보이는지
- [ ] 미리 돌려 둘 것(그 자리용과 다른 자료로): 포스터 1장 등록, 강의자료 1개 요약, 공고 1개 준비하기
- [ ] **데모 때 보일 알림을 정해 둔다**: 마감 D-3·D-1 알림은 그날 09:00(KST)에 만들어지니, 데모 날 마감이 D-1이나 D-3인 공고를 넣어 두면 알림함에 와 있다. 새 과제 알림은 LMS에 새 과제가 올라와야 생기므로(동기화 30분), 실시간 푸시를 기대하지 말고 알림함에 온 것을 보여 준다
- [ ] 웹 푸시: 데모 노트북 Chrome에서 알림 허용, OS 방해 금지 끄기, 설정 → 알림의 "푸시 알림 켜기"와 "이 브라우저에서 알림 받기"를 켠다(뒤의 것은 `NEXT_PUBLIC_VAPID_PUBLIC_KEY`가 없으면 안 보인다. iOS는 쓰지 않는다 — PRD 12장)
- [ ] 노트북 백업 두 가지를 켜 본다: 목 모드 빌드 화면, 로컬 시험 DB의 `app.eval.cli`
- [ ] 리허설을 처음부터 끝까지 한 번 돌리고 시간을 잰다(아래 기록)

## 당일 (시작 1시간 전)

- [ ] 데모 노트북: 충전기, 화면 밝기, 브라우저 확대 125%, 북마크 줄 숨김, 다른 탭·메신저·메일 알림 끄기
- [ ] 데모 전용 Chrome 프로필로 로그인해 둔다(로그인 화면부터 보여 줄 거면 로그아웃해 둔다)
- [ ] 홈이 뜨고, 공고 상세 하나가 열리고, 처리 과정이 펼쳐진다
- [ ] 모델 한 번: 연습용 포스터를 하나 올려 확인 화면까지 가 본다(Gemini가 답하는지). 데모에 쓸 포스터는 아껴 둔다
- [ ] 백업 확인: 노트북의 목 모드 화면, 백업 영상 파일, 지표 표(`docs/베이스라인.md`)를 바로 열 수 있다
- [ ] 화면 공유 때 터미널·`.env`·Supabase 대시보드 창이 안 보인다

## 데모 중

- 모델 단계가 30초를 넘으면 기다리지 말고 미리 돌려 둔 결과로 넘어간다("뒤에서 계속 돌고 있어요. 미리 돌려 둔 결과로 볼게요")
- 실패 안내가 나오면 그대로 읽는다 — 오류 문구는 무엇을 하면 되는지 쓰도록 만들었다
- 질문이 판정 근거로 가면 공고 상세의 조건별 결과와 처리 과정을 연다(LLM은 요건 구조화까지만, 판정은 코드)

## 끝난 뒤

- [ ] 팀원의 LearningX 토큰을 계속 쓸 게 아니면 LMS에서 지운다
- [ ] 배포한 api를 평소로 되돌린다: 최소 인스턴스 0(`docs/배포_절차.md` 8장)
- [ ] 화면 녹화본에 개인정보·토큰이 없는지 다시 본다
- [ ] 그날 돈 실행을 `GET /internal/metrics`로 본다(`X-Internal-Key`가 필요하니 화면 밖에서). 필요하면 `docs/베이스라인.md`에 한 절 더한다
