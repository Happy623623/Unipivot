# 로그인 진단 — 거절 이유 로그, 시계 차이 60초, 서버 문제는 503

> 📝 기준: PRD v0.9 F-01 · API 명세 v0.4 1·13장 · `계정API연결_구현.md`(실제 모드 환경과 로그인) · `공고API연결_구현.md`(이 PR을 정한 곳) · 2026-10-13
>
> 함께 보는 파일: `계정API연결_구현.md`, `공고API연결_구현.md`, `학위과정_구현.md`(먼저 합친다). 모두 레포에 들어가 있어야 한다

로그인한 뒤에도 "로그인이 만료됐어요"가 반복되면 지금은 이유를 알 수 없다. API가 토큰을 거절한 이유를 남기지 않고, 공개키를 받지 못하는 서버 문제도 401로 돌려줘서 웹이 로그인 화면으로 보낸다. 다시 로그인해도 같은 곳을 맴돈다. `공고API연결_구현.md`에서 정한 작은 PR이다.
- **로그:** 토큰을 거절하면 uvicorn 터미널에 `로그인 확인 실패(401): 이유. 고칠 곳` 한 줄이 남는다. 토큰·비밀키·DB 비밀번호는 남기지 않는다.
- **시계 차이:** 60초까지 허용한다. PC 시계가 조금 늦어도 방금 받은 토큰을 "아직 유효하지 않음"으로 거절하지 않는다.
- **서버 문제는 503:** `SUPABASE_URL`이 비었거나 틀렸거나 공개키를 받지 못하면 503 `AUTH_UNAVAILABLE`이다. 웹은 503이면 로그인 화면으로 보내지 않고 화면마다 있는 불러오기 실패 안내를 보인다. 웹 화면 코드는 그대로다.
- **시작 점검:** API를 켤 때 `SUPABASE_URL`이 비었거나 예시 값이면 경고 한 줄을 남긴다. 환경 점검 스크립트는 따로 넣지 않는다.
- **웹 로그인 콜백:** 코드 교환·캘린더 토큰 저장·세션 갱신이 실패하면 `npm run dev` 터미널에 단계와 이유를 남긴다. 이동하는 화면은 그대로다.

**규모와 확인:**
- 새 파일 1개(api 테스트), 바꾸는 파일 4개(api 3개, web 1개). DB와 화면은 바뀌지 않는다.
- api 테스트 29개를 더했다. Linux `379 passed, 35 skipped`, DB를 붙이면 `414 passed`다. 새 동작을 하나씩 되돌리는 시험 19가지가 모두 테스트에 걸렸다.
- web은 `tsc`와 `next build`를 목 모드와 실제 모드로 통과했다.
- 실제 uvicorn과 가짜 공개키 서버로 23단계, 실제 모드 웹으로 6단계를 확인했다. 앞 PR의 실제 모드 88단계도 그대로 통과했다.
- 검토 에이전트 2개가 차례로 봤다. 잘못 넣은 DB 주소의 비밀번호가 로그에 남는 경로, 꾸민 토큰으로 생기는 500(PR 전부터 있던 것) 등 지적 10가지를 모두 받아들였다.

## 정한 것

| 항목 | 정한 것 | 이유 |
| --- | --- | --- |
| 401과 503 | · 401 `UNAUTHORIZED`(토큰 문제): 토큰 없음, 만료, 서명이 틀림, 공개키 목록에 토큰의 키가 없음(다른 프로젝트의 토큰, 바뀐 키), 토큰 모양이 틀림<br>· 503 `AUTH_UNAVAILABLE`(서버 문제): `SUPABASE_URL`이 비었거나 틀림, 공개키를 받지 못함(연결 실패·시간 초과), 받은 응답이 공개키 목록이 아님(JSON이 아님, 빈 목록, 모양이 틀림)<br>· 503 문구: "로그인을 확인하지 못했어요. 잠시 후 다시 시도해 주세요." | 웹은 401이면 로그인 화면으로 보낸다(`계정API연결_구현.md`). 서버 문제에 401을 주면 다시 로그인해도 같은 곳을 맴돈다. `DB_UNAVAILABLE`처럼 503으로 둔다 |
| 시계 차이 | 60초까지 허용한다(발급 시각·만료 시각 모두). 2분 전에 만료된 토큰은 401이다 | Supabase가 준 토큰의 발급 시각이 이 PC 시계보다 앞서면 "아직 유효하지 않음"으로 거절된다. PC 시계는 동기화가 꺼져 있으면 몇십 초까지 틀어질 수 있다. 만료된 토큰을 1분 더 받는 정도는 토큰 수명(1시간)에 비해 작다 |
| 거절 이유 로그 | · 401: `로그인 확인 실패(401): 예외 이름: 이유. 고칠 곳`(WARNING)<br>· 503: `로그인 확인 실패(503): 이유. 고칠 곳`(ERROR)<br>· 토큰과 비밀키는 남기지 않는다. 예외 문구는 한 줄로 줄이고, 제어 문자는 `\x1b`처럼 적고, 200자로 자른다 | 예외 문구에 토큰 머리의 kid가 들어간다. kid는 요청이 정하는 값이라 줄바꿈·제어 문자로 가짜 로그 줄을 만들 수 있다 |
| 고칠 곳 | 흔한 설정 실수만 짚는다: PC 시계가 늦음, 비밀키를 채운 서버에 새 프로젝트 토큰, 비밀키가 다른 프로젝트 값, 웹과 API의 프로젝트가 다름, 공개키로 검증하는 서버에 레거시 토큰, 공개키 목록이 빔, 연결 실패. 아래 "로그 읽는 법" | 지금은 `.env`의 무엇이 틀렸는지 알 방법이 없다 |
| `SUPABASE_URL` 점검 | 비었음, 계정 정보(`@`)가 있음, `http(s)://`로 시작하지 않음, 예시 값(`<…>`)이 남음. 값은 `http(s)://`로 시작하고 `@`가 없을 때만 로그에 보여 준다. 문제가 있으면 공개키를 받으러 가지 않는다 | DB 주소나 키를 잘못 넣었을 때 비밀번호·키가 로그에 남지 않게 한다 |
| 시작 점검 | API를 켤 때 위 점검을 한 번 하고, 문제가 있으면 `로그인 설정 확인: …` 한 줄을 남긴다. 앱은 그대로 뜬다(로그인이 필요 없는 `/health`는 된다) | 첫 요청을 기다리지 않고 알린다 |
| 환경 점검 스크립트 | 레포에 넣지 않는다. 같은 점검을 API가 켤 때와 요청마다 한다 | API가 실제로 읽은 설정을 본다. 스크립트를 따로 두면 점검이 두 군데가 되어 서로 어긋날 수 있다 |
| 공개키 | · 토큰의 kid로 찾고, 찾은 키는 기억한다(PyJWT 캐시). 공개키 주소가 잠깐 안 돼도 아는 키의 토큰은 검증한다<br>· 모르는 kid면 목록을 다시 받는다. 받은 지 30초 안이면 다시 받지 않는다(PyJWT 기본)<br>· 받는 데 10초를 넘기면 실패(503)다(전에는 30초). 주소 끝의 `/`와 앞뒤 공백은 뗀다<br>· 찾은 키를 PyJWK째 넘긴다. 토큰의 alg가 그 키의 알고리즘과 다르면 401이다 | 공개키를 받는 동안 그 요청이 기다린다.<br>키 값만 넘기면 RS256 토큰에 EC 키가 걸릴 때 500이었다(PR 전부터) |
| 의존성 | `get_current_user`를 동기 함수로 바꿨다. FastAPI가 스레드에서 돌린다 | 공개키를 받는 동안 다른 요청을 막지 않는다 |
| 웹 로그인 콜백 | 코드 교환, 캘린더 토큰 저장(응답 상태·오류 코드, 연결 실패), 로그인한 사용자 확인, 세션 새로 받기가 실패하면 `[auth/callback] 단계 실패 { name, code, status, message, cause }`를 남긴다. 값은 200자로 자르고 코드·토큰·쿠키는 남기지 않는다 | 로그인이 실패해도 어느 단계인지 알 수 없었다 |

### 로그 읽는 법

uvicorn 터미널(API):

| 로그 | 뜻 | 할 일 |
| --- | --- | --- |
| `로그인 설정 확인: SUPABASE_URL이 …`(켤 때)<br>`로그인 확인 실패(503): SUPABASE_URL이 …`(요청마다) | `SUPABASE_URL`이 비었거나 틀렸다. 로그인이 필요한 요청이 모두 503이다 | 그 줄대로 `api/.env`를 고치고 uvicorn을 다시 켠다. `--reload`는 `.env`를 고쳐도 다시 뜨지 않는다 |
| `로그인 확인 실패(401): ExpiredSignatureError: Signature has expired` | 만료된 토큰이다(1분 여유를 넘김) | 다시 로그인한다 |
| `… ImmatureSignatureError: The token is not yet valid (iat). 이 컴퓨터 시계가 1분 넘게 늦을 수 있어요. 시간 동기화를 켜세요` | PC 시계가 1분 넘게 늦다 | 아래 "Windows에서"의 시계 맞추기 |
| `… InvalidAlgorithmError: The specified alg value is not allowed. 새 Supabase 프로젝트의 토큰(ES256)이에요. api/.env의 SUPABASE_JWT_SECRET을 비우세요` | 비밀키(HS256)로 검증하는데 토큰은 새 방식(ES256)이다 | `SUPABASE_JWT_SECRET`을 비우고 `SUPABASE_URL`을 채운다 |
| `… InvalidSignatureError: Signature verification failed. SUPABASE_JWT_SECRET이 이 프로젝트의 값인지 확인하세요` | 비밀키가 다른 프로젝트의 값이다 | Supabase 대시보드의 JWT 설정과 맞춘다 |
| `… PyJWKClientError: Unable to find a signing key that matches: "…". 웹(.env.local)과 API(.env)가 같은 Supabase 프로젝트 주소를 쓰는지 확인하세요` | 공개키 목록에 토큰의 키가 없다 | `web/.env.local`의 `NEXT_PUBLIC_SUPABASE_URL`과 `api/.env`의 `SUPABASE_URL`을 같은 프로젝트로 맞춘다 |
| `… 레거시(HS256) 토큰이에요. 이 프로젝트면 api/.env에 SUPABASE_JWT_SECRET을 채우세요` | 레거시 프로젝트의 토큰을 공개키로 검증하려 했다 | `SUPABASE_JWT_SECRET`을 채운다 |
| `로그인 확인 실패(503): 공개키를 받지 못했어요(https://….supabase.co/auth/v1/.well-known/jwks.json). PyJWKClientConnectionError: …. api/.env의 SUPABASE_URL과 네트워크를 확인하세요` | 공개키 주소에 닿지 못했거나 응답이 공개키 목록이 아니다 | 주소 오타와 인터넷 연결을 확인한다 |
| `… PyJWKSetError: The JWK Set did not contain any keys. 공개키가 없는 레거시 프로젝트면 api/.env의 SUPABASE_JWT_SECRET을 채우세요` | 공개키 목록이 비었다 | 레거시 프로젝트면 `SUPABASE_JWT_SECRET`을 채운다 |

## 합친 뒤 실제로 눌러 보기

- [ ] **서버:** `api`는 `uv run uvicorn app.main:app --reload`, `web`은 `npm run dev`로 띄운다(터미널 따로).
- [ ] **켤 때:** uvicorn 터미널에 `로그인 설정 확인:`으로 시작하는 줄이 없어야 한다. 있으면 그 줄대로 `api/.env`를 고치고 uvicorn을 다시 켠다.
- [ ] **로그인·홈:** 로그인해서 홈과 설정을 연다. 평소처럼 보이고, uvicorn 터미널에 `로그인 확인 실패`가 없어야 한다. 있으면 위 "로그 읽는 법"대로 고친다.
- [ ] **(선택) 503 보기:** `api/.env`의 `SUPABASE_JWT_SECRET`이 비어 있을 때(공개키로 검증할 때)만 해당한다.
  - `SUPABASE_URL` 맨 끝에 `x`를 붙여 저장하고 uvicorn을 다시 켠다.
  - 홈을 새로 고치면 로그인 화면으로 가지 않고 "공고를 불러오지 못했어요. 잠시 후 새로 고쳐 주세요."가 보인다. uvicorn 터미널에는 `로그인 확인 실패(503): 공개키를 받지 못했어요(…)`가 나온다.
  - `x`를 지우고 uvicorn을 다시 켠다.
- [ ] 로그인이 다시 안 되면 uvicorn 터미널의 `로그인 확인 실패` 줄과 `npm run dev` 터미널의 `[auth/callback]` 줄을 붙여 준다. 토큰·비밀번호는 들어 있지 않다.

**되돌리기 시험 19가지:** 아래를 하나씩 되돌리면 테스트가 실패했다.
- 나누기: 시계 여유 0초, 모르는 키도 503, 공개키 실패를 401로, 받기·읽기 실패를 잡지 않음, 예전처럼 좁게 잡음(이상한 응답이 500), 키 값만 넘김(alg가 다른 토큰이 500), 주소 점검 없이 공개키 받기
- 고칠 곳: 레거시 프로젝트, 시계, 비밀키 비우기, 다른 프로젝트, 레거시 토큰
- 로그: 줄바꿈을 그대로 둠, 제어 문자를 그대로 둠, 길이를 자르지 않음, 예시 값 점검, 계정 정보가 든 주소를 보여 줌, http가 아닌 값을 보여 줌, 켤 때 경고

**실제 uvicorn 23단계:** 마이그레이션을 모두 적용한 Postgres와 가짜 공개키 서버(ES256)로 돌렸다.

| 묶음 | 본 것 |
| --- | --- |
| 공개키 정상 | ES256 토큰 200. 발급 30초 뒤·30초 전 만료 200, 2분 전 만료 401. 모르는 키 401. 로그에 만료 이유와 다른 프로젝트 안내가 있고 토큰은 없다. 켤 때 경고 없음 |
| 꾸민 토큰 | alg가 키와 다른 토큰(RS256 + EC 키의 kid) 401. 제어 문자가 든 kid 401, 로그에는 `\x1b`로 적힌다 |
| 공개키 서버 꺼짐 | 503 `AUTH_UNAVAILABLE`과 문구. 로그에 공개키 주소, 연결 오류, 고칠 곳 |
| 빈 공개키 목록 | 503, 레거시 프로젝트 안내 |
| 예시 값 주소 | 켤 때 경고, 요청 503, 공개키를 받으러 가지 않고 바로 이유를 남김 |
| 비밀키 서버에 새 프로젝트 토큰 | 401, 비밀키를 비우라는 안내 |

**실제 모드 웹 6단계:** API를 예시 값 주소로 띄워 모든 요청이 503일 때, 홈에 머물고 "공고를 불러오지 못했어요. 잠시 후 새로 고쳐 주세요."가 보인다(로그인 화면으로 가지 않음). 잘못된 코드로 로그인 콜백을 열면 `/login?error=auth`로 가고, Next 서버 로그에 `[auth/callback] 로그인 코드 교환 실패`와 이유가 남는다. 코드 값은 남지 않는다.

**앞 PR 실제 모드 88단계:** 비밀키(HS256) 경로로 홈·상세·정보 입력·설정을 눌렀다. 그대로 통과했다.

검토 에이전트 2개가 차례로 봤다. 아래를 모두 받아들였다.

| 차례 | 지적 | 고친 것 |
| --- | --- | --- |
| 1 | `SUPABASE_URL`에 DB 주소를 잘못 넣으면 503 로그에 DB 비밀번호가 남는다 | 값은 `http(s)://`로 시작하고 `@`가 없을 때만 보여 준다. 공개키를 받기 전에 점검한다 |
| 1 | 실패를 나누려고 공개키 목록을 요청마다 먼저 확인해서, 목록 캐시(5분)가 지난 뒤 공개키 주소가 안 되면 아는 키의 토큰도 실패했다(전에는 찾은 키를 기억해서 됐다) | 목록을 먼저 보지 않고 kid로 찾는다. 아는 키 테스트를 더했다 |
| 1 | 토큰 머리의 kid를 줄바꿈째 로그에 남겨 가짜 로그 줄을 만들 수 있다 | 한 줄로 줄이고 200자로 자른다 |
| 1 | 모르는 kid라 공개키를 다시 받다가 실패하면 401이다 | 503 |
| 1 | async 의존성에서 공개키를 받느라 그동안 다른 요청이 멈춘다 | 동기 함수로 바꿔 스레드에서 돈다 |
| 1 | 공개키 목록이 빈 레거시 프로젝트에 맞는 안내가 없다 | "레거시 프로젝트면 SUPABASE_JWT_SECRET을 채우세요" |

| 2 | ESC 같은 제어 문자가 그대로 남아 터미널의 줄을 지우고 가짜 줄을 쓸 수 있다 | `\x1b`처럼 적는다 |

```python
"""Supabase access token 검증 (API 명세 1장 인증). 실패 이유는 로그에 남기고 토큰은 남기지 않는다.

- 토큰 문제(만료·위조·다른 프로젝트의 토큰): 401 UNAUTHORIZED. 웹이 로그인 화면으로 보낸다
- 서버 문제(SUPABASE_URL이 비었거나 틀림, 공개키를 받지 못함): 503 AUTH_UNAVAILABLE. 401을 주면 웹이
  로그인 화면으로 보내서, 다시 로그인해도 같은 곳을 맴돈다
"""

import logging
from dataclasses import dataclass
from datetime import timedelta
from functools import lru_cache
from typing import Annotated, Any

import jwt
from fastapi import Depends, Header

from app.config import Settings, get_settings
from app.errors import ApiError

logger = logging.getLogger(__name__)

# 서버와 이 컴퓨터의 시계가 조금 달라도 방금 받은 토큰을 "아직 유효하지 않음(iat)"이나 만료로 거절하지 않는다
CLOCK_LEEWAY = timedelta(seconds=60)
JWKS_TIMEOUT_SECONDS = 10  # 공개키를 받는 동안 그 요청이 기다리므로 오래 끌지 않는다
AUTH_UNAVAILABLE = "로그인을 확인하지 못했어요. 잠시 후 다시 시도해 주세요."
_KID_NOT_FOUND = "Unable to find a signing key"  # PyJWKClient: 받은 공개키 목록에 토큰의 kid가 없음


@dataclass(frozen=True)
class CurrentUser:
    id: str
    email: str | None
    name: str | None


@lru_cache
def _jwks_client(jwks_url: str) -> jwt.PyJWKClient:
    # cache_keys: 한 번 찾은 키는 기억해서, 공개키 주소가 잠깐 안 돼도 아는 키의 토큰은 계속 검증한다
    return jwt.PyJWKClient(jwks_url, cache_keys=True, timeout=JWKS_TIMEOUT_SECONDS)


def auth_settings_problem(settings: Settings) -> str | None:
    """로그인 확인 설정에서 고칠 점. 없으면 None이다. 앱을 시작할 때와 공개키를 받기 전에 본다.

    주소는 http(s)://로 시작하고 계정 정보(@)가 없을 때만 그대로 보여 준다. 잘못 넣은 DB 주소의 비밀번호나
    키가 로그에 남지 않게 한다."""
    if settings.supabase_jwt_secret:
        return None  # 레거시 HS256 비밀키로 검증해서 주소를 쓰지 않는다
    url = settings.supabase_url.strip()
    if not url:
        return "SUPABASE_URL이 비어 있어요(api/.env). 로그인이 필요한 요청이 모두 503이 돼요"
    if "@" in url:
        return (
            "SUPABASE_URL에 계정 정보(@)가 들어 있어요(값은 보여 주지 않음). DB 주소 대신"
            " Supabase 프로젝트 주소(https://….supabase.co)를 넣으세요"
        )
    if not url.lower().startswith(("https://", "http://")):
        return "SUPABASE_URL이 https://로 시작하지 않아요(값은 보여 주지 않음). Supabase 프로젝트 주소를 넣으세요"
    if "<" in url or ">" in url:
        return f"SUPABASE_URL에 예시 값이 남아 있어요: {url}. Supabase 프로젝트 주소로 바꾸세요"
    return None


def decode_supabase_token(token: str, settings: Settings) -> dict[str, Any]:
    """Supabase access token을 검증한다.

    레거시 프로젝트는 HS256 비밀키(SUPABASE_JWT_SECRET)로,
    새 프로젝트는 {SUPABASE_URL}/auth/v1/.well-known/jwks.json 공개키로 검증한다.
    """
    try:
        if settings.supabase_jwt_secret:
            return jwt.decode(
                token,
                settings.supabase_jwt_secret,
                algorithms=["HS256"],
                audience="authenticated",
                leeway=CLOCK_LEEWAY,
            )
        return jwt.decode(
            token,
            _signing_key(token, settings),
            algorithms=["ES256", "RS256"],
            audience="authenticated",
            leeway=CLOCK_LEEWAY,
        )
    except jwt.PyJWTError as exc:
        # 오류 문구에 토큰 머리(kid 등)가 들어갈 수 있어 한 줄로 줄이고 길이를 자른다(가림 처리도 받는다)
        logger.warning(
            "로그인 확인 실패(401): %s: %s%s",
            type(exc).__name__,
            _one_line(str(exc)),
            _hint(exc, settings, token),
        )
        raise ApiError(401, "UNAUTHORIZED", "로그인이 만료됐어요. 다시 로그인해 주세요.") from exc


def _signing_key(token: str, settings: Settings) -> jwt.PyJWK:
    """토큰의 kid에 맞는 공개키.

    토큰 머리가 틀렸거나 받은 목록에 kid가 없으면 토큰 문제(401, PyJWTError 그대로)다.
    공개키를 받거나 읽다가 난 문제는 모두 서버 문제(503)다.
    PyJWK를 그대로 넘겨서, 토큰의 alg가 키의 알고리즘과 다르면 decode가 401로 거절한다(500이 아님).
    """
    if problem := auth_settings_problem(settings):
        raise _unavailable(problem)
    kid = jwt.get_unverified_header(token).get("kid")
    jwks_url = f"{settings.supabase_url.strip().rstrip('/')}/auth/v1/.well-known/jwks.json"
    try:
        return _jwks_client(jwks_url).get_signing_key(kid)
    except jwt.PyJWKClientError as exc:
        if str(exc).startswith(_KID_NOT_FOUND):
            raise  # 다른 프로젝트의 토큰이거나 바뀐 키(401)
        raise _unavailable(_fetch_failure(jwks_url, exc)) from exc
    except Exception as exc:  # 빈 목록, JSON이 아니거나 모양이 틀린 응답, 읽다 끊김
        raise _unavailable(_fetch_failure(jwks_url, exc)) from exc


def _fetch_failure(jwks_url: str, exc: Exception) -> str:
    reason = f"공개키를 받지 못했어요({jwks_url}). {type(exc).__name__}: {_one_line(str(exc))}"
    if "did not contain any" in str(exc):  # 키 목록이 비었음
        return (
            reason + ". 공개키가 없는 레거시 프로젝트면 api/.env의 SUPABASE_JWT_SECRET을 채우세요"
        )
    return reason + ". api/.env의 SUPABASE_URL과 네트워크를 확인하세요"


def _unavailable(reason: str) -> ApiError:
    logger.error("로그인 확인 실패(503): %s", reason)
    return ApiError(503, "AUTH_UNAVAILABLE", AUTH_UNAVAILABLE)


def _one_line(text: str) -> str:
    """로그 한 줄: 줄바꿈을 없애고, 제어 문자는 \\x1b처럼 적고, 200자로 자른다.

    요청에서 온 값(토큰 머리의 kid 등)이 가짜 로그 줄을 만들거나 터미널을 조작하지 못하게 한다."""
    flat = " ".join(text.split())
    escaped = "".join(c if c.isprintable() else c.encode("unicode_escape").decode() for c in flat)
    return escaped[:200]


def _hint(exc: jwt.PyJWTError, settings: Settings, token: str) -> str:
    """로그에 붙이는 고칠 곳. 흔한 설정 실수만 짚는다."""
    if isinstance(exc, jwt.ImmatureSignatureError):
        return ". 이 컴퓨터 시계가 1분 넘게 늦을 수 있어요. 시간 동기화를 켜세요"
    if settings.supabase_jwt_secret and isinstance(exc, jwt.InvalidAlgorithmError):
        return (
            ". 새 Supabase 프로젝트의 토큰(ES256)이에요. api/.env의 SUPABASE_JWT_SECRET을 비우세요"
        )
    if settings.supabase_jwt_secret and isinstance(exc, jwt.InvalidSignatureError):
        return ". SUPABASE_JWT_SECRET이 이 프로젝트의 값인지 확인하세요"
    if isinstance(exc, jwt.PyJWKClientError):
        if _algorithm(token) == "HS256":
            return ". 레거시(HS256) 토큰이에요. 이 프로젝트면 api/.env에 SUPABASE_JWT_SECRET을 채우세요"
        return ". 웹(.env.local)과 API(.env)가 같은 Supabase 프로젝트 주소를 쓰는지 확인하세요"
    return ""


def _algorithm(token: str) -> str | None:
    try:
        return jwt.get_unverified_header(token).get("alg")
    except jwt.PyJWTError:
        return None


def get_current_user(
    settings: Annotated[Settings, Depends(get_settings)],
    authorization: Annotated[str | None, Header()] = None,
) -> CurrentUser:
    """동기 함수라서 FastAPI가 스레드에서 돌린다. 공개키를 받는 동안 다른 요청을 막지 않는다."""
    if not authorization or not authorization.lower().startswith("bearer "):
        raise ApiError(401, "UNAUTHORIZED", "로그인이 필요해요.")
    claims = decode_supabase_token(authorization.split(" ", 1)[1], settings)
    if not claims.get("sub"):
        raise ApiError(401, "UNAUTHORIZED", "로그인 정보가 올바르지 않아요.")
    metadata = claims.get("user_metadata") or {}
    return CurrentUser(
        id=claims["sub"],
        email=claims.get("email"),
        name=metadata.get("full_name") or metadata.get("name"),
    )


CurrentUserDep = Annotated[CurrentUser, Depends(get_current_user)]
```

```python
@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    settings: Settings = app.state.settings
    # 로그인 설정이 틀렸으면 첫 요청을 기다리지 않고 시작할 때 알린다(.env를 고치면 서버를 다시 켠다)
    if problem := auth_settings_problem(settings):
        logger.warning("로그인 설정 확인: %s", problem)
    app.state.pool = app.state.log_pool = None
    if settings.database_url:
        app.state.pool, app.state.log_pool = create_pools(settings.database_url)
        await app.state.pool.open()
        await app.state.log_pool.open()
    yield
    for pool in (app.state.pool, app.state.log_pool):
        if pool is not None:
            await pool.close()


def create_app(settings: Settings | None = None) -> FastAPI:
    install_log_redaction()  # 로그에서 토큰을 가린다 (요청 처리 전에 건다)
    settings = settings or get_settings()
    app = FastAPI(title="UNIPIVOT API", version="0.2.0", lifespan=lifespan)
    app.state.settings = settings
    # 나중에 추가한 미들웨어가 바깥이다. 예외로 생긴 500에도 CORS 헤더가 붙게 CORS를 바깥에 둔다
    app.add_middleware(UnhandledErrorMiddleware)
    app.add_middleware(
        CORSMiddleware,
        allow_origins=settings.cors_origins,
        allow_credentials=True,
        allow_methods=["*"],
        allow_headers=["*"],
    )
    register_error_handlers(app)
    app.include_router(health.router)
    for router in (auth.router, me.router, meta.router, events.router, opportunities.router):
        app.include_router(router, prefix=settings.api_prefix)
    return app


app = create_app()
```

```python
class StaticJwks(jwt.PyJWKClient):
    """네트워크 없이 정해 둔 응답(또는 예외)을 차례로 돌려주는 공개키 클라이언트.

        self._last_successful_fetch = time.monotonic()
        return response
```

```ts
import { isAuthApiError, isAuthSessionMissingError, type SupabaseClient } from "@supabase/supabase-js";
import { cookies } from "next/headers";
import { NextResponse } from "next/server";
import { safeNextPath, withQuery } from "@/lib/redirectPath";
import { createReadOnlyServerSupabase, createServerSupabase } from "@/lib/supabase/server";

// 로그인과 캘린더 연결이 함께 쓰는 콜백 (API 4장, 증분 승인)
// - 로그인: 세션만 만든다. 동의 전이면 홈의 AppFrame이 /onboarding으로 보낸다
// - 캘린더 연결(connect=calendar): Google 토큰을 백엔드에 한 번 넘겨 암호화 저장한다
// 어느 쪽이든 Google 토큰(provider_token·provider_refresh_token)은 브라우저 쿠키에 남기지 않는다.
// 코드 교환 직후 세션에만 실려 오므로, 세션을 한 번 새로 받아 Google 토큰이 없는 세션으로 바꾼다
export async function GET(request: Request) {
  const { searchParams, origin } = new URL(request.url);
  const code = searchParams.get("code");
  const next = safeNextPath(searchParams.get("next"));
  const connectCalendar = searchParams.get("connect") === "calendar";
  const toLogin = (reason: string) => NextResponse.redirect(`${origin}/login?error=${reason}`);
  // 캘린더 연결은 실패해도 로그인을 그대로 두고 원래 화면으로 돌려보낸다
  const backWith = (result: string) => NextResponse.redirect(`${origin}${withQuery(next, "calendar", result)}`);
  // Google 화면에서 취소·거절하면 code 없이 돌아온다
  if (!code) return connectCalendar ? backWith("error") : toLogin("missing_code");

  // 캘린더 연결 전에 로그인해 있던 사용자. Google에서 다른 계정을 고르면 세션이 그 계정으로 바뀌므로 비교한다
  const before = connectCalendar ? await signedInUserId() : null;
  if (before === undefined) return backWith("error");

  const supabase = await createServerSupabase();
  const { data, error } = await supabase.auth.exchangeCodeForSession(code);
  if (error || !data.session) {
    logFailure("로그인 코드 교환", error ?? "세션 없음");
    return connectCalendar ? backWith("error") : toLogin("auth");
  }
  if (!connectCalendar) {
    return (await dropGoogleTokens(supabase)) ? NextResponse.redirect(`${origin}${next}`) : toLogin("auth");
  }
  if (before && before !== data.session.user.id) {
    // 다른 계정의 토큰은 저장하지 않고, 바뀐 세션도 이 기기에서 지운다. 처음 계정으로 다시 로그인하게 한다
    // TODO: 처음 쓰는 Google 계정이었다면 Supabase 사용자만 생기고 남는다. 정리는 탈퇴(DELETE /me) 작업 때 정한다
    await endSession(supabase);
    return toLogin("other_account");
  }

  const { access_token, provider_token, provider_refresh_token } = data.session;
  let result = "error";
  try {
    const response = await fetch(`${process.env.NEXT_PUBLIC_API_BASE_URL}/auth/google/tokens`, {
      method: "POST",
      headers: { "Content-Type": "application/json", Authorization: `Bearer ${access_token}` },
      body: JSON.stringify({ provider_token, provider_refresh_token }),
    });
    if (response.ok) result = "connected";
    else logFailure("캘린더 토큰 저장", { status: response.status, code: await errorCode(response) });
  } catch (caught) {
    // 백엔드에 닿지 못해도 로그인 세션은 그대로 두고, 돌아간 화면에서 다시 연결하게 한다
    logFailure("캘린더 토큰 저장(API 연결)", caught);
  }
  // refresh token을 못 받았을 때(422 GOOGLE_REFRESH_TOKEN_MISSING)도 error로 돌아가 다시 연결을 안내한다
  return (await dropGoogleTokens(supabase)) ? backWith(result) : toLogin("auth");
}

// 지금 로그인한 사용자 id. 세션이 없거나 끊겼으면 null(새 로그인처럼 진행), Auth 서버 오류로 확인하지 못하면 undefined.
// 쿠키를 바꾸지 않는 클라이언트로 확인한다(세션이 끊겨 있으면 auth-js가 PKCE 값까지 지워 교환이 실패한다)
async function signedInUserId(): Promise<string | null | undefined> {
  const { data, error } = await (await createReadOnlyServerSupabase()).auth.getUser();
  if (data.user) return data.user.id;
  const gone = isAuthSessionMissingError(error) || (isAuthApiError(error) && error.status < 500 && error.status !== 429);
  if (error && !gone) logFailure("로그인한 사용자 확인", error);
  return !error || gone ? null : undefined;
}

// 세션을 새로 받아 Google 토큰이 없는 세션으로 바꾼다. 실패하면 Google 토큰이 남지 않게 이 기기에서 로그아웃한다
async function dropGoogleTokens(supabase: SupabaseClient): Promise<boolean> {
  const { error } = await supabase.auth.refreshSession();
  if (!error) return true;
  logFailure("세션 새로 받기", error);
  await endSession(supabase);
  return false;
}

// 이 기기의 세션을 끝낸다. 로그아웃 요청이 실패해도 세션 쿠키는 지운다
async function endSession(supabase: SupabaseClient): Promise<void> {
  await supabase.auth.signOut({ scope: "local" });
  const cookieStore = await cookies();
  for (const { name } of cookieStore.getAll()) {
    if (name.startsWith("sb-") && name.includes("-auth-token")) cookieStore.delete(name);
  }
}

// 실패 이유를 서버 로그(npm run dev 터미널)에 남긴다. 토큰·코드 값은 남기지 않는다.
// fetch 실패는 cause에 연결 오류 코드(ECONNREFUSED 등)가 있다
function logFailure(step: string, reason: unknown): void {
  const fields = typeof reason === "object" && reason !== null ? (reason as Record<string, unknown>) : { message: reason };
  const cause = fields.cause as { code?: unknown } | undefined;
  const detail = Object.fromEntries(
    Object.entries({ name: fields.name, code: fields.code, status: fields.status, message: fields.message, cause: cause?.code })
      .filter(([, value]) => value !== undefined && value !== null)
      .map(([key, value]) => [key, String(value).slice(0, 200)]),
  );
  console.warn(`[auth/callback] ${step} 실패`, detail);
}

// API 오류 응답의 code(API 명세 13장). 본문을 읽지 못하면 null
async function errorCode(response: Response): Promise<string | null> {
  const body = await response.json().catch(() => null);
  return typeof body?.error?.code === "string" ? body.error.code : null;
}
```
